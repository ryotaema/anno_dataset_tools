# anno_dataset_tools

アノテーション済みデータセットの整理・形式変換・分割を行うツール群．
学習を回す前のデータ整形用にまとめました．
(対応形式 : YOLO, Pascal VOC, CVAT)

## セットアップ

```bash
# GUI に必要
sudo apt install python3-tk

# 任意（あると便利）
pip install pyyaml   # data.yaml からクラス名を読む
pip install tqdm     # CLI スクリプトの進捗表示
```

標準ライブラリ以外の必須依存はありません．

## 全体の流れ

収集からアノテーション・学習までは次のように繋がります．

```
[1] 収集      real_syutoku / nyx660_syutoku
              → d435_260707_101741_00042_c.jpg のような自己完結した名前で保存
                （旧命名のデータは各リポジトリの tools/rename_legacy_gui.py で変換）
                                ↓
[2] まとめる  dataset_manager_gui.py ＞ まとめるタブ
              → 散らばった収集データを1フォルダに集約（必要なら zip）
                                ↓
[3] アノテーション  labelImg / CVAT
                                ↓
[4] 検証      dataset_manager_gui.py ＞ 検証タブ
              → 座標の異常・重複ラベル・孤立ファイルを洗い出す
                                ↓
[5] 整理      dataset_manager_gui.py ＞ 概要 / 抽出・間引きタブ
              → 内訳を見て偏りを直す、必要な分だけ取り出す
                                ↓
[6] 分割      dataset_manager_gui.py ＞ 分割タブ
              → train/val/test（data.yaml 付きで出力）
                                ↓
[7] 学習
```

[1] の命名規則でカメラ・取得日・セッションがファイル名から読み取れるため、
[2] で1つのフォルダにまとめた後でも [5] で「どのカメラの・いつのデータが何%か」を
集計でき、[6] でセッション単位の分割（情報漏れの防止）ができます．

## データセット整理ツール（GUI）

```bash
python3 dataset_manager_gui.py
```

データセットを読み込むと、内訳の確認から分割・抽出・検証・変換までを1つの画面で行えます．
`tkinter` が必要です（`sudo apt install python3-tk`）．

上部でデータセットを**複数**読み込み、それを下のタブが共通のデータ源として使います．

```
┌ データセット（複数読み込めます）──────────────────────┐
│ /home/.../sam_ws/dataset          A   4,408   4,408   2  │
│ /home/.../260624_pepper           C   1,200   1,180   2  │
└──────────────────────────────────────────┘
 合計 5,608 件 / ラベル付き 5,588 件 / BBox 18,204 個 / クラス 2 種
┌[概要][まとめる][分割][抽出・間引き][検証][変換]────────┐
```

読み込み時にレイアウトを自動判別します．

| 記号 | 構造 |
|---|---|
| A | `images/*.jpg` + `labels/*.txt` |
| B | `images/train/*.jpg` + `labels/train/*.txt` |
| C | `train/images/*.jpg` + `train/labels/*.txt` |
| D | 同一フォルダに画像と `.txt` が混在（labelImg の既定） |

クラス名は `classes.txt` / `labels/classes.txt` / `data.yaml` から自動で読み込みます．

### 共通の操作手順

ファイルを書き出すタブ（まとめる・分割・抽出）は、どれも同じ2ステップです．

1. 出力フォルダなどを設定して **「① プレビューを作成」** を押す
   → 何件がどこに、どんな内訳で出るかが表に出ます
2. 内容を確認して、タブ下部の **「② …を実行」** を押す
   → 確認ダイアログのあと書き出します

**プレビューを作るまで ② のボタンは押せません**（グレーアウト）．
設定を変えると再びグレーに戻るので、必ず最新の内容を確認してから実行できます．
進捗と結果はウィンドウ下部の進捗バーとログに出ます．

### 概要 — 内訳を枚数と割合で見る

クラス・カメラ・取得日・セッション・split・取得元・モダリティ別に、枚数と割合を棒付きで表示します．

```
区分                          枚数     割合                       BBox数
0: bell_pepper               4,133    93.8%  █████████████████·   14,491
1: pedicle                     995    22.6%  ████·············     1,204
(ラベルなし)                    275     6.2%  █················         0
合計（画像）                  4,408                                16,639
```

1枚に複数クラスが写っている場合は各クラスに1枚ずつ数えるため、割合の合計が
100% を超えることがあります（上の例では 93.8% + 22.6% + 6.2%）．

カメラ・取得日・セッションは、`real_syutoku` / `nyx660_syutoku` の命名規則
（`d435_260707_101741_00042_c.jpg`）から自動で読み取ります．
規則に当てはまらない画像は「不明」にまとめられます．CSV に保存もできます．

### まとめる — 散らばったデータを1つにする

複数の場所にあるデータセットを1つのフォルダに集約します．アノテーション用に
まとめたり、CVAT へのアップロード用に zip にしたりできます．

- 出力形式：`images/ labels/`（アノテーション用）/ YOLO 標準 / `images/train/`
- 元の train/val を維持するか、解除して1つにするかを選択
- ラベルのない画像を含めるかどうか
- **ファイル名が衝突したら取得元フォルダ名を頭に付けて回避**（何が変わるか実行前に一覧表示）
- 終わったらそのまま zip にする

### 分割 — train / val / test に分ける

**割合でも枚数でも指定できます．**

| 指定方法 | 例 | 動作 |
|---|---|---|
| 割合 | train 80% / val 20% | 全体をその比率で分ける |
| 枚数 | train 800 / val 200 / test 100 | 指定枚数だけ取り出す（残りは使わない） |

「まとまりの単位」で、分割時に**ばらしてはいけない単位**を指定できます．

| 単位 | 用途 |
|---|---|
| 画像ごと | 従来どおり1枚ずつ振り分ける |
| ショット | 同じショットの color/depth/IR を同じ split に入れる |
| セッション | 同じセッションの画像を同じ split に入れる |

定点タイムラプスや連続収録では隣接フレームがほとんど同じ画像なので、それが
train と val に分かれると val の成績が実力より良く出ます（情報漏れ）．
セッション単位にすればこれを防げます．なお、セッションは途中で切れないため、
枚数指定でも指定値ちょうどにはなりません（プレビューに注意書きが出ます）．

クラス比を保つ stratified 分割にも対応．実行前に split ごとのクラス構成を確認できます．

```
split / クラス            枚数     割合
▼ train                  3,526    80.0%  ██████████████·
     0: bell_pepper      3,306    93.8%
     (ラベルなし)           220     6.2%
▼ val                      882    20.0%  ███············
```

### 抽出・間引き — 条件を指定して取り出す

カメラ・取得日・セッション・クラス・split で絞り込み、枚数または割合の上限で間引きます．

- 「d435 の 6月分から 500 枚」
- 「全体の 30% だけ取り出す」
- 「クラスごとに 300 枚まで」（クラス不均衡の是正）

選び方は4種類．既定は `spread` です．

| 選び方 | 動作 | 再現性 |
|---|---|---|
| `spread` | セッションから均等に取り、**セッション内は等間隔**に選ぶ | 常に同じ結果 |
| `spread_random` | セッションから均等に取り、**セッション内はランダム**に選ぶ | seed で決まる |
| `random` | 全体からランダムに選ぶ | seed で決まる |
| `head` | 先頭から順に選ぶ | 常に同じ結果 |

3セッション（各10ショット）から6枚取り出したときの違い：

```
spread          08:00→[1, 6]   12:00→[1, 6]    16:00→[1, 6]     セッションも時刻も均等
spread_random   08:00→[7, 9]   12:00→[3, 10]   16:00→[5, 8]     セッションは均等・中身は無作為
random          08:00→[7]      12:00→[1,5,10]  16:00→[3, 7]     セッションごとの枚数が偏る
head            08:00→[1,2,3,4,5,6]                             最初のセッションだけ
```

`spread` はセッション内でも撮影時刻がまんべんなく散るため、
「1回の撮影の最初の数枚だけ」に偏りません．タイムラプスのように
長時間のセッションを間引くときに有効です．

セッションごとの枚数が違う場合（10枚 / 3枚 / 20枚 から 9枚）は、
持っている分が少ないセッションはその全部を使い、残りを他から均等に取ります．

```
spread   08:00→[1, 4, 7]   12:00→[1, 2, 3]（全部）   16:00→[1, 7, 14]
```

**命名規則の対象外データ**（旧命名や外部データセット）はセッションが取れないため、
`spread` を選んでも自動的に `random` と同じ動作になります．
その場合はプレビューとログにその旨が表示されます．

### 検証

`scripts/anno_validator.py` の検査を読み込み済みデータセットにかけます．
座標の範囲外・極小/極大 BBox・IoU による重複ラベル・孤立ファイル・クラス不足を
一覧表示し、JSON に保存できます．

### 変換

- YOLO → Pascal VOC
- Pascal VOC → YOLO
- CVAT XML → YOLO
- CVAT XML → YOLO-pose

`classes.txt` を空欄にすると、読み込み済みデータセットのクラス定義を使います．

## コマンドライン版

GUI を使わず個別に実行することもできます（従来どおり）．
バッチ処理や CI に組み込む場合はこちらを使ってください．

```bash
# データセットの分割（フォルダ選択ダイアログが出ます）
python3 scripts/split_dataset.py --train_ratio 0.8 --val_ratio 0.2 --stratified

# アノテーション品質チェック（ERROR があれば exit code 1）
python3 scripts/anno_validator.py --labels_dir ./dataset/labels \
    --images_dir ./dataset/images --class_file ./classes.txt \
    --report_json ./validation_report.json

# 形式変換
python3 scripts/yolo_to_pascal.py --yolo_labels_dir L --yolo_images_dir I --voc_save_dir O
python3 scripts/pascal_to_yolo.py --voc_dir V --img_dir I --yolo_save_dir O
```

CLI 版の `split_dataset.py` は割合指定のみです．枚数指定・セッション単位の分割・
複数データセットの同時処理は GUI の分割タブを使ってください．

## ファイル構成

```
anno_dataset_tools/
├── dataset_manager_gui.py       # 統合GUI の起動口
├── dsm/                         # GUI と共通で使う処理
│   ├── naming.py                #   ファイル名から カメラ/日付/セッション を読む
│   ├── dataset.py               #   データセットの走査・レイアウト判別・集計
│   ├── ops.py                   #   分割・絞り込み・間引き・出力・zip
│   └── gui/                     #   画面（タブごとに1ファイル）
├── scripts/                     # CLI（従来どおり単体で動きます）
│   ├── split_dataset.py         #   train/val/test 分割
│   ├── anno_validator.py        #   アノテーション品質チェック
│   ├── yolo_to_pascal.py        #   YOLO → Pascal VOC
│   └── pascal_to_yolo.py        #   Pascal VOC → YOLO
└── cvat_conv/
    ├── cvat_to_yolo.py          # CVAT XML → YOLO
    └── cvat_to_yolo_pose.py     # CVAT XML → YOLO-pose
```

GUI は `scripts/anno_validator.py` と `cvat_conv/` をそのまま呼び出しているので、
検査・変換のロジックは CLI と GUI で同一です．
