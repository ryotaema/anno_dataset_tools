# anno_dataset_tools

アノテーション済みデータセットの整理・形式変換・分割を行うツール群．
学習を回す前のデータ整形用にまとめました．
(対応形式 : YOLO, Pascal VOC, CVAT)

## セットアップ

```bash
# GUI に必要
sudo apt install python3-tk

# 動画→画像タブ / extract_frames.py に必要
pip install opencv-python

# 任意（あると便利）
pip install pyyaml   # data.yaml からクラス名を読む
pip install tqdm     # CLI スクリプトの進捗表示
```

動画から画像を取り出す機能だけ `opencv-python` が必要で、それ以外は標準ライブラリだけで動きます．
（opencv が無くても他のタブは従来どおり使えます）

## 全体の流れ

収集からアノテーション・学習までは次のように繋がります．

```
[0] 動画→画像 dataset_manager_gui.py ＞ 動画→画像タブ
              → mp4 などから nyx_260810_143000_00001_cv.jpg として切り出す
                （動画で撮った素材を使う場合のみ）
                                ↓
[1] 収集      real_syutoku / nyx660_syutoku
              → d435_260707_101741_00042_c.jpg のような自己完結した名前で保存
                （旧命名・セッション間で重複する名前は ＞ 名前変更タブ でそろえる）
                                ↓
[2] まとめる  dataset_manager_gui.py ＞ まとめるタブ
              → 散らばった収集データを1フォルダに集約（必要なら zip）
                                ↓
[3] アノテーション  labelImg / CVAT
                                ↓
[4] 検証      dataset_manager_gui.py ＞ 検証タブ
              → 座標の異常・重複ラベル・孤立ファイルを洗い出す
                                ↓
[5] 整理      dataset_manager_gui.py ＞ 概要 / 抽出・間引きタブ
              → 内訳を見て偏りを直す、必要な分だけ取り出す
                                ↓
[6] 分割      dataset_manager_gui.py ＞ 分割タブ
              → train/val/test（data.yaml 付きで出力）
                                ↓
[7] 学習
```

[0] [1] の命名規則でカメラ・取得日・セッションがファイル名から読み取れるため、
[2] で1つのフォルダにまとめた後でも [5] で「どのカメラの・いつのデータが何%か」を
集計でき、[6] でセッション単位の分割（情報漏れの防止）ができます．

ファイル名がこの規則から外れていると [5] [6] の恩恵を受けられないうえ、
**セッションが違うのに同じ名前**（`1color.jpg` など）だと [2] でまとめた時点で
衝突します．心当たりがあれば先に**名前変更タブ**でそろえてください．

## データセット整理ツール（GUI）

```bash
python3 dataset_manager_gui.py
```

動画からの切り出し・名前の整理から、内訳の確認・分割・抽出・検証・変換までを
1つの画面で行えます．`tkinter` が必要です（`sudo apt install python3-tk`）．

上部でデータセットを**複数**読み込み、それを下のタブが共通のデータ源として使います．

```
┌ データセット（複数読み込めます）──────────────────────┐
│ /home/.../sam_ws/dataset          A   4,408   4,408   2  │
│ /home/.../260624_pepper           C   1,200   1,180   2  │
└──────────────────────────────────────────┘
 合計 5,608 件 / ラベル付き 5,588 件 / BBox 18,204 個 / クラス 2 種
┌[概要][まとめる][分割][抽出・間引き][検証][変換][動画→画像][名前変更]┐
```

右端の2つ（動画→画像・名前変更）はアノテーション前の下ごしらえ用で、
上の一覧ではなく**フォルダを直接指定**して動きます．残りは読み込んだデータセットを使います．

読み込み時にレイアウトを自動判別します．

| 記号 | 構造 |
|---|---|
| A | `images/*.jpg` + `labels/*.txt` |
| B | `images/train/*.jpg` + `labels/train/*.txt` |
| C | `train/images/*.jpg` + `train/labels/*.txt` |
| D | 同一フォルダに画像と `.txt` が混在（labelImg の既定） |

クラス名は `classes.txt` / `labels/classes.txt` / `data.yaml` から自動で読み込みます．

### 共通の操作手順

ファイルを書き出すタブ（動画→画像・名前変更・まとめる・分割・抽出）は、どれも同じ2ステップです．

1. 出力フォルダなどを設定して **「① プレビューを作成」** を押す
   → 何件がどこに、どんな内訳で出るかが表に出ます
2. 内容を確認して、タブ下部の **「② …を実行」** を押す
   → 確認ダイアログのあと書き出します

**プレビューを作るまで ② のボタンは押せません**（グレーアウト）．
設定を変えると再びグレーに戻るので、必ず最新の内容を確認してから実行できます．
進捗と結果はウィンドウ下部の進捗バーとログに出ます．

### 概要 — 内訳を枚数と割合で見る

クラス・カメラ・取得日・セッション・split・取得元・モダリティ別に、枚数と割合を棒付きで表示します．

```
区分                          枚数     割合                       BBox数
0: bell_pepper               4,133    93.8%  █████████████████·   14,491
1: pedicle                     995    22.6%  ████·············     1,204
(ラベルなし)                    275     6.2%  █················         0
合計（画像）                  4,408                                16,639
```

1枚に複数クラスが写っている場合は各クラスに1枚ずつ数えるため、割合の合計が
100% を超えることがあります（上の例では 93.8% + 22.6% + 6.2%）．

カメラ・取得日・セッションは、`real_syutoku` / `nyx660_syutoku` の命名規則
（`d435_260707_101741_00042_c.jpg`）から自動で読み取ります．
規則に当てはまらない画像は「不明」にまとめられます．CSV に保存もできます．

### まとめる — 散らばったデータを1つにする

複数の場所にあるデータセットを1つのフォルダに集約します．アノテーション用に
まとめたり、CVAT へのアップロード用に zip にしたりできます．

- 出力形式：`images/ labels/`（アノテーション用）/ YOLO 標準 / `images/train/`
- 元の train/val を維持するか、解除して1つにするかを選択
- ラベルのない画像を含めるかどうか
- **ファイル名が衝突したら取得元フォルダ名を頭に付けて回避**（何が変わるか実行前に一覧表示）
- 終わったらそのまま zip にする

### 分割 — train / val / test に分ける

**割合でも枚数でも指定できます．**

| 指定方法 | 例 | 動作 |
|---|---|---|
| 割合 | train 80% / val 20% | 全体をその比率で分ける |
| 枚数 | train 800 / val 200 / test 100 | 指定枚数だけ取り出す（残りは使わない） |

「まとまりの単位」で、分割時に**ばらしてはいけない単位**を指定できます．

| 単位 | 用途 |
|---|---|
| 画像ごと | 従来どおり1枚ずつ振り分ける |
| ショット | 同じショットの color/depth/IR を同じ split に入れる |
| セッション | 同じセッションの画像を同じ split に入れる |

定点タイムラプスや連続収録では隣接フレームがほとんど同じ画像なので、それが
train と val に分かれると val の成績が実力より良く出ます（情報漏れ）．
セッション単位にすればこれを防げます．なお、セッションは途中で切れないため、
枚数指定でも指定値ちょうどにはなりません（プレビューに注意書きが出ます）．

クラス比を保つ stratified 分割にも対応．実行前に split ごとのクラス構成を確認できます．

```
split / クラス            枚数     割合
▼ train                  3,526    80.0%  ██████████████·
     0: bell_pepper      3,306    93.8%
     (ラベルなし)           220     6.2%
▼ val                      882    20.0%  ███············
```

### 抽出・間引き — 条件を指定して取り出す

カメラ・取得日・セッション・クラス・split で絞り込み、枚数または割合の上限で間引きます．

- 「d435 の 6月分から 500 枚」
- 「全体の 30% だけ取り出す」
- 「クラスごとに 300 枚まで」（クラス不均衡の是正）

選び方は4種類．既定は `spread` です．

| 選び方 | 動作 | 再現性 |
|---|---|---|
| `spread` | セッションから均等に取り、**セッション内は等間隔**に選ぶ | 常に同じ結果 |
| `spread_random` | セッションから均等に取り、**セッション内はランダム**に選ぶ | seed で決まる |
| `random` | 全体からランダムに選ぶ | seed で決まる |
| `head` | 先頭から順に選ぶ | 常に同じ結果 |

3セッション（各10ショット）から6枚取り出したときの違い：

```
spread          08:00→[1, 6]   12:00→[1, 6]    16:00→[1, 6]     セッションも時刻も均等
spread_random   08:00→[7, 9]   12:00→[3, 10]   16:00→[5, 8]     セッションは均等・中身は無作為
random          08:00→[7]      12:00→[1,5,10]  16:00→[3, 7]     セッションごとの枚数が偏る
head            08:00→[1,2,3,4,5,6]                             最初のセッションだけ
```

`spread` はセッション内でも撮影時刻がまんべんなく散るため、
「1回の撮影の最初の数枚だけ」に偏りません．タイムラプスのように
長時間のセッションを間引くときに有効です．

セッションごとの枚数が違う場合（10枚 / 3枚 / 20枚 から 9枚）は、
持っている分が少ないセッションはその全部を使い、残りを他から均等に取ります．

```
spread   08:00→[1, 4, 7]   12:00→[1, 2, 3]（全部）   16:00→[1, 7, 14]
```

**命名規則の対象外データ**（旧命名や外部データセット）はセッションが取れないため、
`spread` を選んでも自動的に `random` と同じ動作になります．
その場合はプレビューとログにその旨が表示されます．

### 検証

`scripts/anno_validator.py` の検査を読み込み済みデータセットにかけます．
座標の範囲外・極小/極大 BBox・IoU による重複ラベル・孤立ファイル・クラス不足を
一覧表示し、JSON に保存できます．

### 変換

- YOLO → Pascal VOC
- Pascal VOC → YOLO
- CVAT XML → YOLO
- CVAT XML → YOLO-pose

`classes.txt` を空欄にすると、読み込み済みデータセットのクラス定義を使います．

### 動画→画像 — mp4 などからフレームを切り出す

動画ファイル1本でも、動画の入ったフォルダごとでも指定できます．

**取り出す量**は5通りで指定できます．

| 指定方法 | 例 | 動作 |
|---|---|---|
| N 秒ごと | 1 秒 | 一定の時間間隔で取る（既定） |
| N フレームごと | 30 フレーム | フレーム番号で間引く |
| 毎秒 N 枚 | 2 枚/秒 | 目標 FPS を決めて取る |
| 全体から N 枚 | 100 枚 | 動画全体に散らして N 枚だけ取る |
| 全フレーム | — | 間引かずすべて取る |

さらに**範囲**（開始・終了時刻）と**上限枚数**（1動画あたり／全体）を組み合わせられます．
上限に当たったときは先頭から詰めるのではなく、等間隔に間引いて全体に散らします．

**採用しなかったフレーム（残り）**は3通りから選べます．

| 残りの扱い | 動作 |
|---|---|
| 破棄する | 使わない（既定） |
| すべて `_rest/` に出す | 予備プール．あとから追加のデータが欲しくなったときに使う |
| 間引いて `_rest/` に出す | 「5秒ごと」など枚数を抑えて予備を残す（ディスク節約） |

**品質フィルタ**（どちらも任意）．アノテーションの手間を無駄にしないための機能です．
**どちらも閾値を大きくするほど厳しくなり、残る枚数が減ります．**

| フィルタ | 測っているもの | 閾値の目安 |
|---|---|---|
| 似すぎたフレームを飛ばす | 直前に**採用した**フレームとの絵の違い（0〜255） | 0 に近い＝ほぼ同じ絵／1〜3＝わずかな揺れ（既定 2.0）／10 以上＝構図が変わっている |
| ブレた画像を弾く | 輪郭のはっきり具合（Laplacian 分散） | 被写体・解像度で桁が変わるため**絶対的な目安なし**．実測して決める |

閾値をいくつにすればよいか分からないときは、**「フィルタの説明と試算...」**を押してください．
仕組みの説明と、実際の動画を少しだけ読み込んだ**実測値**、そして
**閾値ごとに何枚残るか**の表が出ます．表の行をダブルクリックするとその値が反映されます．

```
似すぎ判定の閾値          残る枚数（見込み）    弾かれる枚数
  0.5                     40 / 40（約 320 枚）        0
  2.0                     31 / 40（約 248 枚）        9
  8.0                     12 / 40（約  96 枚）       28
いまの設定（似すぎ 2.0 / ブレ 100）→ サンプル 40 枚中 31 枚が残る見込み
```

弾いたフレームは「フィルタで弾いた分も `_rest/` に残す」（既定ON）にしておけば
捨てられずに残るので、厳しすぎた場合に拾い直せます．
このとき、プレビューの枚数には `+α` と付きます．フィルタで何枚弾かれるかは
実際にデコードするまで決まらないため、**抽出はプレビューの数より減り、
減った分だけ `_rest/` が増えます**（確定した枚数は実行後にログに出ます）．

**出力ファイル名**は収集スクリプトと同じ命名規則にそろえます．

```
{cam}_{YYMMDD}_{HHMMSS}_{NNNNN}_{mod}.jpg
nyx_260810_143000_00001_cv.jpg
```

- カメラは `vid` / `d435` / `d405` / `nyx` から選ぶか、自分で入力できます
  （動画のファイル名にカメラ名が入っていれば拾います）
- 日時は「ファイル名から読む」「動画ファイルの更新時刻」「手入力」から選べます
- モダリティは末尾に **`v`（動画由来）** が付きます（color → `cv` / depth → `dv`）

**1本の動画＝1セッション**として扱うため、抽出した直後から概要タブのカメラ・取得日・
セッション集計が効き、分割タブで**セッション単位の分割**ができます．

動画から取り出した画像は隣接フレームがほとんど同じなので、1枚ずつ train と val に
振り分けると val の成績が実力より良く出ます（情報漏れ）．**分割タブで「まとまりの単位」を
セッションにしてください**．動画データで最も引っかかりやすい落とし穴です．

プレビューでは動画ごとの長さ・FPS・解像度・抽出枚数・出力名の例と、サムネイルが出ます．
同じ名前のファイルが出力先に既にある場合（同じ動画を出し直したときなど）は
**上書きになる件数**を先に知らせます．
実行後、出力フォルダには抽出条件を記録した `metadata.json` が残ります．

### 名前変更 — 画像とラベルの名前を一括で変える

`0color.jpg` `1color.jpg` … のように、**セッションが違っても同じ名前**が使われていると、
1つのフォルダに集約した時点で衝突し、学習時にどのデータか追えなくなります．
ファイル名そのものに「どのデータか」を書き込んでおくためのタブです．

```
260101_house/color/1color.jpg  →  260101_house_1color_c.jpg
```

フォルダを選ぶと**親フォルダ名から候補を提案**します（そのまま書き換えられます）．
名前の作り方は3通りです．

| 方法 | 内容 |
|---|---|
| かんたん | 先頭・末尾に付ける文字列を直接入力する |
| テンプレート | `{parent2}_{stem}_{mod}` のようにトークンで組み立てる |
| 標準命名 | `{cam}_{YYMMDD}_{HHMMSS}_{NNNNN}_{mod}` に変換する |

テンプレートで使えるトークン：

| トークン | 内容 |
|---|---|
| `{stem}` | 元のファイル名（拡張子なし） |
| `{parent}` `{parent2}` `{parent3}` | 1つ上・2つ上・3つ上のフォルダ名 |
| `{mod}` | モダリティ（`color` → `c` / `depth` → `d`／フォルダ名かファイル名から判定） |
| `{n}` | 連番（`{n:05d}` で `00001`） |
| `{cam}` `{date}` `{time}` | 設定欄で指定したカメラ・取得日・時刻 |

**ラベルも同じ名前に追従します**（`.txt` と labelImg の `.xml`）．
ラベルは次の場所から探すので、よくある置き方ならそのまま揃います．

- 画像と同じフォルダ（labelImg の既定）
- パス中の `images` を `labels` に置き換えた場所（`images/labels` 形式・`train/images` 形式）
- 1〜2つ上のフォルダの `labels/`（`260101_house/color` ＋ `260101_house/labels`）

自動で見つからない構成のときは、ラベルの場所を明示することもできます．

**安全のための仕組み**

- **プレビュー**で変更前 → 変更後を一覧表示（ラベルは青、名前が重なる行は赤）
- 変更後の名前が**重複するときは実行できません**（赤で表示）．
  「連番を付けて回避する」（既定ON）なら `_2` `_3` を足して自動で回避します
- `A→B` `B→A` のような入れ替えでも壊れないよう、一時名を経由した2段階で変更します
- 「かんたん」は**すでに付いている先頭・末尾を足しません**．同じ設定で2回実行しても
  `260101_house_260101_house_...` のように二重にはなりません
- 実行内容を `rename_log.json` に記録し、**「元に戻す」**でいつでも元の名前に戻せます
- その場で名前を変えるほかに、**別フォルダにコピー**（原本を残す）も選べます
- 「すでに標準命名のファイルは変えない」で二重変換を防げます

標準命名に変換すると、同じショットの `1color` と `1depth` には同じ連番が振られます．
また、カメラ・取得日・セッションがファイル名から読めるようになるため、
概要タブの集計と分割タブのセッション単位分割が使えるようになります．

## コマンドライン版

GUI を使わず個別に実行することもできます（従来どおり）．
バッチ処理や CI に組み込む場合はこちらを使ってください．

```bash
# 動画から画像を取り出す（既定は dry-run。--apply で実際に書き出す）
python3 scripts/extract_frames.py video.mp4 -o frames/ --every 1s --max 300 --cam nyx
python3 scripts/extract_frames.py videos/ -o frames/ --count 100 \
    --skip-similar --skip-blur --rest thinned:5s --apply

# 名前の一括変更（既定は dry-run。--undo で元に戻す）
python3 scripts/rename_images.py 260101_house/color --prefix 260101_house_ --suffix _c --apply
python3 scripts/rename_images.py 260101_house --template '{parent2}_{stem}_{mod}' --apply
python3 scripts/rename_images.py 260101_house --undo

# データセットの分割（フォルダ選択ダイアログが出ます）
python3 scripts/split_dataset.py --train_ratio 0.8 --val_ratio 0.2 --stratified

# アノテーション品質チェック（ERROR があれば exit code 1）
python3 scripts/anno_validator.py --labels_dir ./dataset/labels \
    --images_dir ./dataset/images --class_file ./classes.txt \
    --report_json ./validation_report.json

# 形式変換
python3 scripts/yolo_to_pascal.py --yolo_labels_dir L --yolo_images_dir I --voc_save_dir O
python3 scripts/pascal_to_yolo.py --voc_dir V --img_dir I --yolo_save_dir O
```

CLI 版の `split_dataset.py` は割合指定のみです．枚数指定・セッション単位の分割・
複数データセットの同時処理は GUI の分割タブを使ってください．

`extract_frames.py` と `rename_images.py` は GUI と同じ処理（`dsm/video.py` /
`dsm/rename.py`）を呼んでいるので、結果は GUI と同一です．どちらも既定は dry-run で、
`--apply` を付けたときだけ書き込みます．使えるトークンの一覧は
`python3 scripts/rename_images.py --tokens` で確認できます．

## ファイル構成

```
anno_dataset_tools/
├── dataset_manager_gui.py       # 統合GUI の起動口
├── dsm/                         # GUI と共通で使う処理
│   ├── naming.py                #   ファイル名から カメラ/日付/セッション を読む
│   ├── dataset.py               #   データセットの走査・レイアウト判別・集計
│   ├── ops.py                   #   分割・絞り込み・間引き・出力・zip
│   ├── video.py                 #   動画からのフレーム抽出（opencv が必要）
│   ├── rename.py                #   名前の一括変更・取り消し
│   └── gui/                     #   画面（タブごとに1ファイル）
├── scripts/                     # CLI（従来どおり単体で動きます）
│   ├── extract_frames.py        #   動画 → 画像
│   ├── rename_images.py         #   名前の一括変更
│   ├── split_dataset.py         #   train/val/test 分割
│   ├── anno_validator.py        #   アノテーション品質チェック
│   ├── yolo_to_pascal.py        #   YOLO → Pascal VOC
│   └── pascal_to_yolo.py        #   Pascal VOC → YOLO
└── cvat_conv/
    ├── cvat_to_yolo.py          # CVAT XML → YOLO
    └── cvat_to_yolo_pose.py     # CVAT XML → YOLO-pose
```

GUI は `scripts/anno_validator.py` と `cvat_conv/` をそのまま呼び出しているので、
検査・変換のロジックは CLI と GUI で同一です．
`extract_frames.py` / `rename_images.py` は逆に `dsm/` の処理を呼び出しています．
